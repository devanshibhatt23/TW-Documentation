# Google Docs for Collaborative Technical Writing

## 1. Introduction
Google Docs is a cloud-based word processor in Google Workspace. It allows people to create and edit documents from different devices. Multiple users can work on the same document, making it useful for reports, assignments, meeting notes and proposals.

Doxygen focuses on code/API documentation, while Google Docs is intended for general documents and collaboration.

## 2. Main features
- Real-time editing by multiple users.
- Formatting with headings, paragraphs, tables, images, links and equations.
- Comments and suggestion mode for review.
- Automatic saving and version history.
- Templates for reports and other documents.
- Import and export in formats such as DOCX, PDF, ODT, RTF, HTML and TXT.

## 3. Creating and structuring a document
A document can start from a blank page or a template. For a technical report, use a title and clear heading hierarchy. Common styles include Title, Subtitle, Heading 1, Heading 2 and Normal Text.

Using heading styles keeps the document consistent and makes it possible to generate a table of contents automatically. It also improves navigation and accessibility.

## 4. Collaboration and sharing
Use **Share** to invite collaborators by email or link. The access roles are:
- **Viewer:** can read the document.
- **Commenter:** can read and add comments.
- **Editor:** can make changes.

Comments can be added, assigned and resolved. Suggesting mode allows a reviewer to propose edits without directly replacing the original text. Users can also see live cursors and changes while collaborating.

## 5. Version history
Google Docs automatically saves changes. To inspect earlier versions, use:

**File → Version history → See version history**

An earlier version can be restored if needed. Important milestones, such as a submission draft or approved copy, can be named.

## 6. Images, drawings, tables and lists
- **Images:** Insert → Image, then select an available source.
- **Drawings:** Insert → Drawing for simple shapes and arrows.
- **Tables:** Insert → Table to organize or compare information.
- **Lists:** Use bullets and numbering to structure points.
- **Checklists:** Useful for collaborative action tracking.

The lecture also mentions integrations such as Lucidchart and diagrams.net for more detailed diagrams.

## 7. Equations and code
The **Insert → Equation** option supports basic LaTeX-style mathematical input through the interface. Short code snippets can be formatted using a monospace font. Larger code blocks may need an add-on or another suitable method.

## 8. Templates and formatting
Built-in templates are available for reports and proposals. Headers, footers and page numbers can be customized. Find/replace, spelling and grammar tools also help during editing. A template is only a starting point; the final document still needs proofreading.

## 9. Citations and bibliography
The citation tool is available under **Tools → Citations**. It supports MLA, APA and Chicago styles. Sources can be added for in-text citations and an automatically generated bibliography. The lecture also mentions integrations with Zotero and Mendeley.

Borrowed ideas, figures and quotations should be acknowledged using the required citation style.

## 10. Exporting and publishing
Documents can be downloaded as PDF, DOCX, ODT, HTML and other formats. They can also be published to the web when public viewing is required. Before sharing, check the access permissions.

## 11. Security and permissions
Google Docs provides document-level sharing permissions. Give collaborators only the access they need, review who can open the document, and avoid making private documents public by mistake. Workspace administrators may also set organization-wide sharing policies.

## 12. Best practices
- Use a consistent style guide and template.
- Organize content with headings and a table of contents.
- Assign reviewing and editing roles.
- Use comments and suggestions for feedback.
- Resolve comments after addressing them.
- Name important versions and export milestone documents.
- Check sharing permissions before distributing a link.

## 13. Doxygen vs. Google Docs
| Feature | Doxygen | Google Docs |
|---|---|---|
| Purpose | Code/API documentation | General documents and reports |
| Collaboration | Usually through code review | Real-time multi-user editing |
| Rich media | Code-linked diagrams and examples | Images, tables and drawings |
| Output | HTML, LaTeX/PDF and others | Web, PDF, Word and others |
| Best for | Source code and APIs | Notes, proposals and specifications |

Both can be used in one project: Google Docs for design notes and reports, and Doxygen for API documentation.

## 14. What I learned
Google Docs is useful when a document needs feedback from more than one person. Headings improve organization, while comments, suggestion mode and version history make reviewing more manageable.
